# ОБЪЕКТ 12 — кооперативный 3D-хоррор в браузере

Сетевой хоррор от первого лица в заброшенном бункере. Процедурная планировка,
тьма, фонарь с садящейся батарейкой и **Смотритель** — слепой твари, которая идёт
на звук шагов и на свет. Один заход — примерно на час.

Всё в проекте сгенерировано кодом: геометрия, текстуры, звук. Никаких внешних
ассетов и CDN — работает офлайн после сборки.

| | |
|---|---|
| Движок | Three.js (WebGL2) + Vite |
| Сеть | WebSocket, JSON-протокол, комнаты, хост-авторитет |
| Игроков | 1–4 (кооператив, общая задача) |
| Сюжет | ремонтная группа спускается на «нулевой этаж» объекта 12 |

## Быстрый запуск

```bash
npm install
npm run build      # собирает dist/
npm start          # http://localhost:3000  (+ WebSocket на /ws)
```

Порт меняется переменной `PORT`:

```bash
PORT=8080 npm start
```

Для разработки: `npm run dev` (Vite, без локального релея — игра уйдёт в
автономный режим, если нет доступа к внешнему узлу).

## Как играть

**Задача.** Найти **5 предохранителей** (по бункеру разбросано 8 — с запасом),
вставить их в генератор в техническом зале, запустить питание и уйти через шлюз.
Дополнительно можно собирать записки — они рассказывают, что случилось в 1987-м.

**Смотритель.** Слепой. Слышит бег на 19 м, шаг — на 10 м, тихий шаг — на 4 м.
Видит свет: включённый фонарь увеличивает его дальность обзора с 15 до 26 метров.
Если он погнался — не бегите по прямой, уходите петлями: коридоры связаны
сквозными проходами. Прячьтесь в шкафах — в них он вас не видит, но помнит, куда
вы шли. После включения генератора он злится и ускоряется.

**Напарники.** Раненого можно поднять: подойдите и держите **E** 4 секунды.
Истекающий кровью умирает за 75 секунд. Мёртвых можно наблюдать.

| Клавиша | Действие |
|---|---|
| W A S D | движение |
| Мышь | обзор (если захват курсора недоступен — зажмите ЛКМ и ведите) |
| Shift | бег (тратит дыхание) |
| Ctrl / C | тихий шаг |
| F | фонарь |
| E | подобрать / вставить / спрятаться / поднять / уйти |
| M / Tab | карта (открывается по мере исследования) |
| T / Enter | чат |
| Esc | пауза |

На телефоне — стик слева, обзор свайпом справа, кнопки действий справа.
Фонарь и карта тоже есть в кнопках.

## Сеть

Приоритет узлов:

1. **`wss://sandbank-economic-zeppelin.ngrok-free.dev`** — внешний релей
   (подключаемся как `wss://…/?room=КОД`). Если он недоступен — переходим дальше.
2. **Локальный релей** того же сервера: `wss://<ваш-хост>/ws?room=КОД`.
3. **Автономный режим** — если не отвечает ничего. Игра полностью играбельна
   в одиночку, Смотритель ведёт себя так же.

Внешний узел может быть любого типа:

* если он отвечает нашим протоколом (`welcome`) — используется серверная
  авторитетность и назначение хоста;
* если это «глупый» широковещательный релей (эхо/трансляция) — включается
  peer-to-peer режим: хоста выбирают по наименьшему `id`, а комнату каждый
  клиент фильтрует сам;
* если соединение не поднимается (например, ngrok отдаёт страницу-предупреждение
  вместо `101 Switching Protocols`) — через 5 секунд идёт фолбэк на локальный
  релей, в HUD это видно. У ngrok бесплатного тарифа страницу-заглушку можно
  один раз пройти в браузере, после чего cookie пропустит и WebSocket.

Сервер на выбор — в стартовом меню («СЕРВЕР»: авто / ngrok / локальный).

**Комната** задаётся в меню или параметром `?room=ABCD`. Ссылка вида
`https://<хост>/?room=ABCD` копируется кнопкой в меню и в паузе. Планировка
бункера детерминирована от кода комнаты: все участники видят один и тот же
лабиринт, даже если подключаются в разное время.

### Протокол (JSON, один общий канал)

Клиент → сервер:

```jsonc
{"t":"hello","id":"<id>","room":"ABCD","name":"ВОРОН"}
{"t":"p","id":"…","room":"ABCD","p":[x,z],"y":yaw,"f":true,"c":false,"hp":90,"dn":false,"dd":false}
{"t":"mon","id":"…","m":{"x":x,"z":z,"yaw":0.4,"state":"chase"}}   // только хост
{"t":"ev","id":"…","k":"pickup|install|obj|hit|noise|scream|revive|down|dead|escape", …}
{"t":"chat","id":"…","text":"привет"}
{"t":"ping","id":"…","ts":12345}
```

Сервер → клиент: `welcome` (id, hostId, seed, peers), `join`, `leave`, `peers`,
`host`, `pong`, а также ретрансляция `p`, `mon`, `ev`, `chat`, `noise` внутри
комнаты. Сообщения `mon` от не-хоста отбрасываются.

Монстр считается только у хоста и рассылается 12 раз в секунду; клиенты
интерполируют позицию. Шаги игроков уходят как `noise`, чтобы слух работал у
всех. Счётчик предохранителей и питание — авторитет хоста (снапшоты `ev/obj`
каждые 2 секунды).

## Структура

```
index.html            разметка экранов и HUD
server.js             статика dist/ + WebSocket-релей комнат
vite.config.js
src/
  main.js             игровой цикл, задачи, события, взаимодействия
  config.js           все константы баланса
  maze.js             генерация лабиринта, BFS-навигация, коллизии, LOS
  world.js            геометрия бункера, свет, предметы, генератор, шлюз, шкафы
  textures.js         процедурные текстуры (canvas)
  player.js           контроллер игрока, стамина, фонарь, камера
  monster.js          ИИ Смотрителя (слух/зрение/погоня) и его модель
  remotePlayers.js    аватары напарников и интерполяция
  net.js              WebSocket-клиент, комнаты, хосты, реконнект
  hud.js              HUD, карта, чат, экраны
  audio.js            весь звук синтезируется через WebAudio
  input.js            клавиатура/мышь/pointer lock и сенсорное управление
  util.js             математика, RNG, хеши
```

## Баланс «на час»

Длина маршрута в лабиринте 41×41 — от 40 до 150 клеток между предохранителями,
по 4 метра клетка. С учётом возврата к генератору, поиска записок, обхода
Смотрителя и посадок фонаря один заход занимает примерно 40–70 минут. Скорость
Смотрителя растёт на 3.5 % за каждую минуту (до +50 %), после включения питания
— ещё +12 %. Света хватает примерно на 6.5 минут на полном заряде, батареек на
карте 11.

---

Если релей на ngrok начнёт отдавать что-то другое (свой протокол, другую схему
сообщений) — достаточно поправить `src/net.js` и `NET.remote` в `src/config.js`:
остальная игра от транспорта не зависит.
